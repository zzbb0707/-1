# GAME-004｜视觉与站位自动验收门禁 V1

## 目的

避免把本可通过实机截图发现的遮挡、错位和截断问题转交给用户发现。该门禁适用于 GAME-004，也作为后续游戏族的最小视觉验证模板。

## 每次布局、素材或配置修改后的固定流程

1. Godot `--headless --editor --quit`：脚本与资源解析。
2. 运行 `tests/test_contract.gd`：App Bridge 和基础数据契约。
3. 运行 `tests/test_slice_configs.gd`：区域数量、规则、范例、对象站位与区域不重叠。
4. 对 L1/L3/L4 分别用 `--write-movie verify_<level>.png --quit-after 2` 生成独立验证帧；禁止覆盖正式素材。
5. 检查三张600×750实机帧，而不是只看Image 2母版。
6. 以下项目任一失败，不得交给用户试玩：
   - 中央对象遮挡选项或热区；
   - 选项热区相互遮挡、越界或与背景语义明显错位；
   - 规则条、范例或底部提示截断；
   - 提示/退出按钮不可见；
   - L1/L3/L4加载错误或背景缺失；
   - 对象标签与提示文字重叠；
   - 低感官模式仍出现强闪烁或高密度动态装饰。
7. 修复后必须重新生成全套验证帧，不能只凭坐标推断已修复。

## 站位数据规范

- 区域使用舞台归一化坐标 `regions[].rect = [x,y,w,h]`。
- 对象使用舞台归一化中心点 `object_position = [x,y]`。
- 配置测试按对象最小安全半径检查与任何区域重叠。
- 对象视觉、对象拖拽热区和区域热区必须来自同一配置，禁止各自写死。
- 正式版可隐藏调试描边，但热区仍必须保留并支持调试视图。

## 证据与留痕

- 验证帧仅放 `artifacts/`，由 `.gitignore` 排除。
- 测试输出保留 `*_TEST_PASS` 标记。
- 候选AI素材保留 manifest、版本和SHA256。
- 提交说明注明验证范围；未执行的屏幕尺寸、设备或App容器必须如实标记未验证。
