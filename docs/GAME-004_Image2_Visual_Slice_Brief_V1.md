# GAME-004｜Image 2 视觉纵切任务书 V1

## 1. 执行职责

- 设计与审核：当前 GAME-004 制作负责人。
- 生成执行：Codex 内置 `image_generation`（Image 2）。
- Codex 只负责按本任务书生成与归档候选图，不得修改玩法、难度、接口或 Godot 代码。
- 所有输出先进入 `assets/candidates/image2/`，状态为 `candidate`；未经审核不得进入 `assets/approved/`。

## 2. 目标不是只画 L1

本批必须证明同一视觉系统能承载 GAME-004 的完整难度递进。先制作三个代表截面：

- `SLICE-L1`：两区、高差异、单规则、强自然结果。
- `SLICE-L3`：三区、规则保持/切换、简单双层类别。
- `SLICE-L4`：四区、范例推断、无关属性干扰、受控例外。

三张必须属于同一个游戏、同一个生态舱、同一套角色/装置/材质/灯光语言，不得像三款独立游戏。

## 3. 统一画面形式

- 风格：风格化 3D 卡通渲染，高品质 3D 动画电影质感；不是2D插画、不是写实摄影、不是低多边形。
- 造型：圆润、玩具化、儿童友好，无尖锐攻击性结构。
- 材质：半写实 PBR，色彩与材质服务生态区域辨识；不继承截图中的青绿机械、黄铜、晶体装置或其他具体世界内容。
- 光照：柔和电影光、清晰体积与轮廓，禁止强闪烁视觉。
- 构图：移动 App 竖屏游戏舞台；上方保留宿主标题/工具栏安全区，底部保留单行提示安全区。
- 主焦点：一次只突出当前对象、当前规则和必要区域；非任务背景降对比。
- 禁止：营销海报构图、纯气氛概念图、复杂背景堆物、文字乱码、伪 UI、大量漂浮粒子、多个同亮度焦点。

## 4. 跨等级固定结构

三张共同保留：

1. 同一主生态舱舞台轮廓；
2. 同一背景视角和固定机位；
3. 中央对象/规则呈现位；
4. 可从2区扩展到4区的模块化生态区域位；
5. 左上或上方的范例/当前规则位（L1可弱化但要预留）；
6. 生态累计变化展示位；
7. 底部提示区；
8. 低干扰的退出/提示按钮安全区。

不得把L1画成无法扩展的两张大卡片。

## 5. 三张母版要求

### 5.1 SLICE-L1

- 两个高差异生态区域：水域与向阳花圃。
- 一个待安排对象，尺寸大、位置明确。
- 水域通过水面、波纹、水生植物表达；花圃通过日照方向、土壤与向光植物表达。
- 不依赖文字才能区分。
- 正确操作后必须有区域专属生态变化，不使用统一烟花。
- 目标：孩子在低压力下理解“它适合哪里”。

### 5.2 SLICE-L3

- 与L1相同舞台，扩展到三区。
- 显示清楚但克制的当前规则标识与规则切换提示位。
- 可支持“先大类、再小类”或受控规则切换。
- 生态已有部分成长，能看出前序结果被保留。
- 难度来自规则变化，不来自更小对象、计时或手速。

### 5.3 SLICE-L4

- 与L1/L3相同舞台，扩展到四区。
- 明确的范例展示位：两个已完成范例帮助孩子推断当前规则。
- 新对象包含一个明显但无关的颜色/外观特征，真正相关特征仍可通过功能或环境理解。
- 四区仍有充足间距和触控尺寸，不做拥挤棋盘。
- 生态状态最丰富，但当前任务焦点仍然唯一。

## 6. 连续生态状态

同一游戏族应支持以下可积累变化：

- 水循环：空水槽 → 水流 → 水草 → 生物返回 → 灌溉连接。
- 光照循环：暗花圃 → 光源 → 向光生长 → 开花 → 储能。
- 维护循环：工具归位 → 装置修复 → 自动维护 → 区域连通。
- 生物循环：选择栖息地 → 安顿 → 互动 → 新生态需求。

L1只展示第一段，L3展示中段，L4展示多系统连接；不能靠三个互不相关的背景表达升级。

## 8. 审核门禁

每张按0–2分审核：

1. 风格参考一致性；
2. 三张系列一致性；
3. 交互焦点清楚；
4. 2/3/4区扩展成立；
5. 触控区域可用；
6. 难度递进可视化但不拥挤；
7. 生态连续成长成立；
8. 可拆分为背景/区域/对象/状态层；
9. 低感官改造潜力；
10. 无乱码、伪UI和明显生成缺陷。

总分低于16/20，或系列一致性/交互焦点任一为0：整批不得进入素材拆分，先修订或更换生成模型。
